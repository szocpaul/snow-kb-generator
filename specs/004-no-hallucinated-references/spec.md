# Feature Specification: Hallucination-Free KB Article Generation

**Feature Branch**: `004-no-hallucinated-references`

**Created**: 2026-07-26

**Status**: Draft

**Input**: User description: "Generated KB articles must under no circumstances contain hallucinated references (e.g. fictional KB article numbers such as KB0012345/KB0012346, which leaked in from the fictional examples of the gold dataset). The system must guarantee that every reference, fact and article number originates from the source Story or from real ServiceNow data."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Gold Dataset Sanitization (Priority: P1)

The gold dataset (`data/examples/gold_dataset.md`) contains fictional KB article numbers in the "Related Articles" sections of the example articles (KB0012345, KB0012346). These get baked into the prompts during GEPA optimization and show up in the generated articles as hallucinated references. The dataset must be cleaned so that the references are unambiguously placeholders, or real references derived from the Story context.

**Why this priority**: The training data is the primary source of the hallucination — as long as the dataset contains fictional article numbers, any re-optimized program will reproduce them.

**Independent Test**: Load the gold dataset and assert that no example article contains a fictional KB number disguised as real (KB + 7-digit pattern that is not the placeholder format).

**Acceptance Scenarios**:

1. **Given** a cleaned gold_dataset.md, **When** a loader loads it, **Then** every "Related Articles" type reference is a placeholder (`KBXXXXXXX`) or "N/A", and no concrete non-existent KB number appears.
2. **Given** the cleaned dataset, **When** the dataset test suite runs, **Then** all tests remain GREEN (the structure is unchanged).

---

### User Story 2 - Hallucination Detection in Metric (Priority: P1)

The `rich_metric` must cover hallucination detection: if the generated article contains a KB article number, URL or concrete fact that does not appear in the input Story text (and is not a placeholder), the metric penalizes it and names it in the feedback.

**Why this priority**: GEPA only improves what the metric measures. Without a hallucination axis, the optimization brings back the fictional references.

**Independent Test**: Testable with a mocked prediction: give a pred with a fictional KB number and a gold without it → the metric score must decrease and the feedback must contain the hallucinated identifier.

**Acceptance Scenarios**:

1. **Given** a pred that contains `KB0012345` and the story_text does NOT contain it, **When** the rich_metric runs, **Then** the hallucination axis is 0 and the feedback contains: "Hallucinated reference: KB0012345".
2. **Given** a pred that contains only KB numbers present in the story_text, **When** the rich_metric runs, **Then** the hallucination axis is 1.0, with no penalty.
3. **Given** a pred that contains a placeholder (`KBXXXXXXX`) or "N/A", **When** the rich_metric runs, **Then** it is not counted as a hallucination.

---

### User Story 3 - Post-Generation Guardrail (Priority: P2)

After generation and before push, the pipeline validates the article: every KB article number reference must either (a) appear in the story_text, or (b) be a placeholder/"N/A". In case of a hallucinated reference, the pipeline removes the reference (strip) or raises an error — it never pushes hallucinated content.

**Why this priority**: Defense-in-depth — even if the metric/GEPA lets something through, no hallucination may escape on the production path (server → ServiceNow).

**Independent Test**: Unit test: the guardrail function removes the reference from HTML containing a hallucinated KB number and leaves the real one untouched.

**Acceptance Scenarios**:

1. **Given** generated HTML with a fictional KB number, **When** the guardrail runs before push, **Then** the fictional reference is removed and the pipeline logs a warning.
2. **Given** generated HTML with a real (story_text-derived) KB number, **When** the guardrail runs, **Then** the HTML stays unchanged.
3. **Given** the FastAPI server, **When** a hallucinated article arrives for push, **Then** the final HTML no longer contains the hallucinated reference.

---

### User Story 4 - Re-optimization with Clean Data (Priority: P3)

With the cleaned dataset + extended metric, re-run the baseline and the GEPA optimization, and export the new `artifacts/program.json`.

**Why this priority**: Only a program optimized on clean data guarantees hallucination-free operation in the long run.

**Independent Test**: Compare the new baseline and optimized scores; the guardrail finds no hallucination in the articles generated by the optimized program on the valset.

**Acceptance Scenarios**:

1. **Given** the new metric and dataset, **When** the baseline re-runs, **Then** `runs/baseline.json` is updated and the hallucination axis is visible in the per-example feedback.
2. **Given** the GEPA re-run, **When** it completes, **Then** the optimized program's valset generations are hallucination-free (validated by a guardrail check).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The gold dataset MUST NOT contain fictional KB article numbers disguised as real; the references are in placeholder (`KBXXXXXXX`) or "N/A" format.
- **FR-002**: The `rich_metric` contains a hallucination axis: KB number patterns found in the generated HTML (KB + ≥6 digits) are compared with the story_text; unknown, non-placeholder identifiers lead to a penalty and explicit feedback.
- **FR-003**: Before push, the pipeline MUST run every article through a `strip_hallucinated_references(html, story_text)` guardrail; the removed references are logged.
- **FR-004**: The guardrail NEVER removes an identifier that appears in the story_text (no false positives).
- **FR-005**: The export of the new optimized program overwrites `artifacts/program.json`; after a server restart the server serves the new version.

### Success Criteria

- **SC-001**: The articles generated on the valset contain 0 hallucinated references (measured by the guardrail).
- **SC-002**: The unit tests of the metric's hallucination axis are GREEN (fictional → penalty, real → no penalty, placeholder → no penalty).
- **SC-003**: The full test suite is GREEN (208+ tests + new ones).
- **SC-004**: After regenerating the production STRY0010010, the article contains no KB0012345/KB0012346 reference.

## Assumptions

- story_text is the only reliable source for KB references; template_context and the gold dataset cannot be considered real data sources.
- The hallucination check is regex-based (KB + digits); validating URLs and other factual claims is the topic of a later feature.
